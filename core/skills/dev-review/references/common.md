# Common Semantic Review Rules

只报告由当前 Task diff 与必要直接上下文支持的问题。检查：

1. 逻辑正确性与需求覆盖。
2. 边界值以及 null、undefined、空数组、空字符串、缺字段。
3. 状态与数据流一致性，loading/error/empty 分支是否可达且完整。
4. async、并发、乱序返回、重复提交和 stale state。
5. 错误传播、恢复路径与资源清理。
6. API 请求/响应/类型契约，兼容旧调用方与旧数据。
7. 权限、敏感信息、注入、开放重定向等安全行为。
8. 明显的重复请求、无界循环/订阅/内存增长和热路径退化。
9. 不必要复杂度、重复状态和与项目既有模式冲突。

不要复述 diff，不报告纯 formatting、命名偏好或缺少“更优雅”抽象。Finding 必须指出具体
触发条件、代码证据和用户/系统影响；证据不足就不报，必要上下文缺失到无法可靠审查才
BLOCKED。
